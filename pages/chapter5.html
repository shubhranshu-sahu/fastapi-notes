1. Creating First FastAPI App

FastAPI() Instance · Route Decorators · Uvicorn Internals · Swagger Docs

🔹 1. What is FastAPI() Instance?
✅ Concept The FastAPI() instance is the core application object that represents your entire web application.

🧠 Explanation (Deep Understanding)

When you write:

python
from fastapi import FastAPI

app = FastAPI()

👉 You are:

  • Creating a web application object
  • Registering a container that will:
    • Handle incoming HTTP requests
    • Route them to correct functions
    • Validate request data
    • Return responses

Internally What Happens?

FastAPI:

  • Builds on Starlette
  • Registers: Routing system, Middleware support, Request/response handling
  • Prepares integration with Pydantic (for validation)
👉 So app = FastAPI() is not just a variable — It is the entry point of your backend

Analogy

ConceptMeaning
app = FastAPI()Your entire backend system
Routes (@app.get)Different API endpoints
UvicornServer that runs the app
🔹 2. Basic Structure of FastAPI App
✅ Minimal Structure
python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def home():
    return {"message": "Hello FastAPI"}

🧠 Explanation Line-by-Line

1. Import from fastapi import FastAPI

Imports the framework

2. Create App Instance app = FastAPI()

Initializes application. All routes will attach to this object.

3. Define Route @app.get("/")

This is called a path operation decorator. It tells "When a GET request comes to /, run this function"

4. Function (Endpoint Logic) def home(): return {…}

Function is called when request hits /. Return value is automatically converted to JSON.

⚡ Important Behavior

👉 You don't write jsonify(...). FastAPI automatically: Converts Python dict → JSON · Sets headers · Handles response

🔹 3. Running with Uvicorn
✅ Concept FastAPI is just a framework — it cannot run itself. You need an ASGI server like Uvicorn.

🧠 Explanation

Uvicorn:

  • Starts your app
  • Listens for HTTP requests
  • Passes them to FastAPI
  • Sends back responses

▶️ Command to Run

bash
uvicorn main:app --reload
PartMeaning
mainfile name (main.py)
appFastAPI instance
--reloadauto restart server on code change

⚡ What Happens Internally

1. Uvicorn starts server 2. Creates event loop (async engine) 3. Loads app 4. Waits for requests 5. Passes request → FastAPI 6. Sends response back
🔹 4. First Endpoint (/)
✅ Concept An endpoint is a URL path + HTTP method that performs an operation.
python
@app.get("/")
def home():
    return {"message": "Hello FastAPI"}

🧠 What Happens When You Visit /

  • Browser sends: GET /
  • FastAPI: Matches route /, Calls home() function
  • Returns: {"message": "Hello FastAPI"}
🔥 Important Feature
  • 👉 Automatic JSON conversion
  • 👉 Automatic status code (200 OK)
🔹 5. Flask vs FastAPI (First App)
🔵 Flask Version
python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return {"message": "Hello Flask"}
⚡ FastAPI Version
python
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def home():
    return {"message": "Hello FastAPI"}

🔹 6. Extra: Interactive API Docs (Huge Advantage)

When you run FastAPI:

👉 Open:

bash
http://127.0.0.1:8000/docs

You get:

  • Swagger UI
  • Test API directly from browser

🧠 Why This is Powerful

  • No need for Postman initially
  • Auto-generated docs
  • Helps frontend + testing
🧠 Interview Notes (Must Remember)
  • FastAPI() is the application instance
  • Routes are defined using decorators like @app.get()
  • FastAPI automatically converts Python objects → JSON
  • Runs using Uvicorn (ASGI server)
  • Built on Starlette + Pydantic
  • Provides automatic Swagger docs at /docs
⚡ Mental Model (Very Important)
👉 Request Flow:
Client → Uvicorn → FastAPI app → Route → Function → Response → Client
🔥 Common Beginner Mistakes
  • Forgetting to install/run Uvicorn
  • Writing wrong command (main:app)
  • Confusing Flask @app.route with FastAPI methods
  • Thinking FastAPI runs without server
