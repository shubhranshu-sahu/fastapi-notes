3. Path Parameters

Dynamic URLs · Type Conversion · Validation · Error Handling · Multiple Params

🔹 1. Dynamic URLs (/items/{id})
✅ Concept Path parameters allow you to create dynamic routes, where part of the URL acts as a variable.
❌ Instead of fixed:
/items/1 /items/2
✅ You write:
/items/{id}

✅ FastAPI Code

python
from fastapi import FastAPI

app = FastAPI()

@app.get("/items/{item_id}")
def get_item(item_id):
    return {"item_id": item_id}

🧠 Explanation

  • "/items/{item_id}" — {item_id} is a dynamic placeholder
  • FastAPI extracts value from URL
  • 👉 Request: GET /items/10 → FastAPI does: item_id = 10
Function Parameter def get_item(item_id): — Parameter name must match {item_id}. FastAPI automatically injects value.

⚔️ Flask Comparison

🔵 Flask
python
@app.route("/items/<item_id>")
def get_item(item_id):
    return {"item_id": item_id}
⚡ FastAPI
python
@app.get("/items/{item_id}")
def get_item(item_id):
    return {"item_id": item_id}
FeatureFastAPIFlask
Syntax{item_id}<item_id>
Type HandlingAutomaticManual
ValidationBuilt-inLimited
🔹 2. Type Conversion (int, str, etc.)
✅ Concept FastAPI uses Python type hints to: Convert data · Validate input
python
@app.get("/items/{item_id}")
def get_item(item_id: int):
    return {"item_id": item_id}

🧠 What Happens Internally

✅ Valid: GET /items/10
"10" (string from URL) → Converted to int(10)
❌ Invalid: GET /items/abc
Cannot convert to int FastAPI throws error automatically
🔥 Supported Types int   str   float   bool
🔹 3. Validation via Type Hints
python
@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id}

🧠 What FastAPI Does

Checks:

  • Is user_id present?
  • Is it integer?
  • If invalid → returns structured error
🧠 Why This is Powerful

👉 You don't write: try/except · manual validation · error responses. FastAPI handles everything using Pydantic.

⚔️ Flask Comparison (Manual)

python
# Flask requires manual validation
@app.route("/users/<user_id>")
def get_user(user_id):
    try:
        user_id = int(user_id)
    except:
        return {"error": "Invalid ID"}, 400

    return {"user_id": user_id}
  • Flask: Manual conversion + Manual error handling
🔹 4. Error Handling (Invalid Types)
python
@app.get("/items/{item_id}")
def get_item(item_id: int):
    return {"item_id": item_id}
🧠 Case 1: Valid Input

GET /items/5

✅ Response: {"item_id": 5}

🧠 Case 2: Invalid Input

GET /items/abc

❌ Auto Error Response:

{
  "detail": [{
    "msg": "value is not a valid integer"
  }]
}
🔥 Important Insight — FastAPI returns:
  • Proper HTTP status code (422)
  • Detailed error message
  • Location of error (path)
🔹 5. Multiple Path Parameters
python
@app.get("/users/{user_id}/orders/{order_id}")
def get_order(user_id: int, order_id: int):
    return {
        "user_id": user_id,
        "order_id": order_id
    }

🧠 Example

GET /users/1/orders/101 
{
  "user_id": 1,
  "order_id": 101
}
🔹 6. Internal Working (Important)

When request comes: GET /items/10

👉 FastAPI: 1. Matches route /items/{item_id} 2. Extracts item_id = "10" 3. Converts → int(10) 4. Validates 5. Calls function 6. Returns JSON
🧠 Interview Notes (Must Remember)
  • Path parameters create dynamic URLs
  • Defined using {param_name}
  • Must match function parameter name
  • Type hints: convert input + validate input
  • FastAPI automatically: handles errors · returns structured response
  • Flask requires manual validation
/items/{id} → dynamic route id: int → validation + conversion invalid → auto error (422)
🔥 Common Mistakes
  • Parameter name mismatch
  • Forgetting type hints
  • Assuming string instead of int
  • Writing Flask-style <id> in FastAPI
