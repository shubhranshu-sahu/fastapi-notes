Chapter 8

4. Path Parameter Order & Routing Priority ⚠️

Static vs Dynamic Routes · The "me" Bug · Order-Based Matching · Best Practices

🔹 1. Static vs Dynamic Routes
📌 Static Route

A route with a fixed path

python
@app.get("/users/me")
def get_current_user():
    return {"user": "current user"}

👉 /users/me → always same

📌 Dynamic Route (Path Parameter)
python
@app.get("/users/{user_id}")
def get_user(user_id: int):
    return {"user_id": user_id}

👉 /users/1, /users/2 → variable

TypeExampleBehavior
Static/users/meExact match
Dynamic/users/{id}Matches anything
🔹 2. The Problem (Very Important) ⚠️
❌ Wrong Order — This will cause bugs!
python
@app.get("/users/{user_id}")    # ← DEFINED FIRST (wrong!)
def get_user(user_id: str):
    return {"user_id": user_id}

@app.get("/users/me")           # ← DEFINED SECOND (never reached for "me")
def get_current_user():
    return {"user": "me"}

🧠 What Happens?

Request: GET /users/me

👉 FastAPI matches: /users/{user_id}

So: user_id = "me"

👉 Output: {"user_id": "me"} ← ❌ WRONG endpoint executed!

🔹 3. Correct Order ✅
python
@app.get("/users/me")           # ← Static FIRST ✅
def get_current_user():
    return {"user": "me"}

@app.get("/users/{user_id}")    # ← Dynamic AFTER ✅
def get_user(user_id: str):
    return {"user_id": user_id}

🧠 Now What Happens?

Request: GET /users/me
  • 👉 FastAPI: First checks /users/me ✅ match
  • Stops searching further
  • 👉 Output: {"user": "me"} ← ✅ CORRECT!
🔹 4. Route Matching Behavior (Deep Understanding)
✅ Rule: FastAPI checks routes top to bottom (in order of definition)

🧠 Internal Working

When request comes: GET /users/me FastAPI: 1. Checks first route 2. If match → execute 3. Else → check next 4. Continues until match
🔥 Important Insight — Dynamic routes are greedy:

They match anything → /users/{anything}

👉 Matches: /users/1 · /users/abc · /users/me ⚠️

🔹 5. Why This Happens

Because: @app.get("/users/{user_id}")

👉 Means: "Match ANY value after /users/"

So: /users/me → user_id = "me"

  • Same issue can occur

🔹 7. Best Practices (VERY IMPORTANT)
✅ Always Define:
  1. Static routes FIRST → @app.get("/users/me")
  2. Dynamic routes AFTER → @app.get("/users/{user_id}")
✅ More Specific → First /users/me ← first /users/{id} ← after /users/{id}/posts ← even more specific
🔹 8. Advanced Example
python
@app.get("/products/latest")      # ← Static FIRST ✅
def latest_product():
    return {"product": "latest"}

@app.get("/products/{product_id}")  # ← Dynamic AFTER ✅
def get_product(product_id: int):
    return {"product_id": product_id}
❌ If reversed:

/products/{product_id} will capture /products/latest → product_id = "latest" → ❌ error or wrong logic

🔹 9. How to Avoid Bugs
✅ Strategy

Think: "Will this dynamic route capture my static route?" If yes → reorder

🔹 10. Interview Explanation (Very Important)

👉 If asked: "Why should /users/me be defined before /users/{id}?"

FastAPI matches routes in the order they are defined. Since dynamic routes like /users/{id} can match any value including "me", defining it first will capture requests meant for static routes like /users/me. Therefore, static routes must always be defined first.
🧠 Key Takeaways
  • Routing is order-dependent
  • Dynamic routes are greedy
  • Static routes must come first
  • More specific → higher priority
  • Same concept applies in Flask
Top → checked first Bottom → checked last Static → first Dynamic → later
🔥 Common Mistakes
  • Writing dynamic routes first
  • Not realizing {id} captures everything
  • Debugging wrong endpoint calls
